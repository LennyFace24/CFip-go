# CFip-go TUI 设计文档

日期：2026-08-14
分支：dev/tui
状态：已批准

## 目标

为 CFip-go 增加终端用户界面（TUI），在终端中以实时、可交互的方式阅读测速结果，替代仅靠日志文本阅读的体验。保留现有 CLI 入口不动。

## 技术选型

- **框架**：charmbracelet/bubbletea（Elm 架构：Model / Update / View）
- **配套组件**：charmbracelet/bubbles（`table` 表格、`spinner` 进度指示）
- **理由**：显式状态结构体 + 消息驱动的三段式架构，业务逻辑透明、可单测，适合开发者自行掌控逻辑；实时进度流天然契合 channel → tea.Cmd 消息。

## 架构

```
cmd/tui/main.go     ← 入口：初始化终端、接线（读配置、解析 IP、启动测速流）
src/tui/model.go    ← 根 Model：全局状态 + 消息定义
src/tui/table.go    ← 结果表格组件（列：IP / 延迟 / 状态 / 来源）
src/tui/status.go   ← 顶部状态栏（进度、成功/失败计数、排序方式、筛选词）
src/tui/keys.go     ← 键位映射与底部帮助栏
src/core/           ← 新增流式测速接口
```

### 包边界

- `src/core`：纯业务，不依赖 TUI。新增流式测速；现有函数不动。
- `src/tui`：纯 UI，不感知文件 IO。通过注入的数据结构渲染。
- `cmd/tui`：接线层，组装依赖，持有全局生命周期。

### 数据流

1. `core.ParseIP(ip.txt 内容)` → `[]IP`（复用现有解析器）
2. 新增 `core.StreamLatency(ctx, ips) <-chan Latency`：流式测速，逐条向 channel 发送结果（成功：延迟值；失败：-1 标记）
3. TUI 订阅 channel：每条结果 → `tea.Cmd` → Update 更新表格行 + 进度计数
4. 集满 `cfg.Number` 个成功结果 → cancel，测速提前结束（与 CLI 语义一致）
5. 测速完成后表格可继续交互（导航/排序/筛选）

## 交互设计

| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 表格行导航 |
| `s` | 循环切换排序：延迟升序 / IP / 状态（成功优先） |
| `/` | 进入筛选输入框，按 IP 子串过滤 |
| `r` | 重新测速（重新解析并启动新测速流） |
| `q` / `ESC` | 退出（`/` 输入状态下 `ESC` 退出筛选） |

## 错误处理

| 场景 | 行为 |
|---|---|
| `config.yml` 加载失败 | TUI 无法启动，打印错误并 panic（与 CLI 一致） |
| `ip.txt` 缺失 | 同上 |
| 终端初始化失败（非 TTY） | 降级：打印错误提示"请在交互式终端中运行"并退出码 1 |
| 测速中 channel 关闭 | 视为测速结束，状态栏显示完成 |

## 测试策略

- `src/core`：流式测速的聚合逻辑（channel 消费、提前停止、失败标记）可单测
- `src/tui`：排序/筛选为纯函数，可单测；不测渲染层
- 现有测试全部保持通过

## 非目标（YAGNI）

- 不做多窗口/标签页
- 不做持久化导出
- 不做触摸/鼠标交互
- 不重构现有 CLI 入口
